## 2024-05-20 - SQL Injection via better-sqlite3 in IPC Handlers
**Vulnerability:** User-controlled inputs (CSV headers, file names, SQLite tables/columns from loaded files, IPC events) were interpolated directly into raw SQL strings using template literals (e.g. `DROP TABLE IF EXISTS "${tableName}"`) instead of being escaped or parameterized. This allowed attackers to craft malicious CSV files or send malicious IPC messages to execute arbitrary SQL, modify the database, or cause a denial of service.
**Learning:** `better-sqlite3` does not support parameterization for SQLite identifiers like table and column names. Because of this, developers sometimes mistakenly use raw string interpolation without escaping the quotes.
**Prevention:** Always manually escape SQLite identifiers (such as table or column names) when string interpolation is necessary in `better-sqlite3` by replacing double quotes with two double quotes (e.g., `.replace(/"/g, '""')`) before injecting them into a query string.
