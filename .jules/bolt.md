## 2025-02-28 - Avoid Chained Array Methods on Large Datasets in React Renders
**Learning:** Chaining array methods like `.map().slice().reduce()` inside a React component's `useMemo` on a large dataset (e.g., query results) can cause multiple O(N) array allocations per column, leading to significant but silent memory bottlenecks and slow execution times.
**Action:** When performing aggregate calculations on large arrays during render, replace chained array methods with a single loop (like a `for` loop) that computes all necessary metrics in one pass to avoid unnecessary memory allocation.
## 2026-10-16 - Prevent Unnecessary Re-renders from Zustand Stores\n**Learning:** Destructuring or invoking the whole store hook (e.g. `const store = useAppStore();`) subscribes the consuming component to *all* state changes in the store. This can cause massive, silent performance bottlenecks across the app when global state updates occur frequently.\n**Action:** Use `useAppStore.getState()` for static references within callbacks, or select only the specific state properties needed (e.g., `const property = useAppStore((state) => state.property);`) instead of calling the hook directly to avoid unintentional subscriptions.

## 2024-05-18 - Prevent Unnecessary Re-renders on Zustand Full Store Subscriptions
**Learning:** Destructuring directly from a Zustand store (e.g., `const { a, b } = useAppStore()`) implicitly subscribes the component to the entire store state. In heavy components, like `EditorCanvas` containing `ReactFlow`, this triggers costly, unnecessary re-renders when completely unrelated state fields (like `theme` or `providerConfigs`) change elsewhere in the app.
**Action:** Always use individual selectors `useAppStore(state => state.property)` or `useShallow` from `zustand/react/shallow` when subscribing to multiple fields, especially for computationally expensive components.
